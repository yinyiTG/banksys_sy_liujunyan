# 01 · 需求 / 活 PRD 〔本项目活记忆 · AI 维护〕

> **作用**:这是本项目唯一的需求文档。所有新功能、缺陷、技术债都追加到这里,不要另起多个 PRD 文件。
> **更新时机**:每次有新需求、需求变更、验收标准变化时更新。

---

## 1. 需求来源

| 类型 | 来源 | 进入方式 |
|---|---|---|
| 功能需求 Feature | 用户 / 老师 / 产品 / 客户 | 写成用户故事 |
| 缺陷 Bug | 测试 / 线上日志 / 用户反馈 | 写复现步骤和期望结果 |
| 技术债 Tech Debt | 开发 / Review / CI/CD 故障 | 写影响和修复目标 |

---

## 2. Issue 生命周期

| 阶段 | 状态 | 动作 |
|---|---|---|
| 提出 | Open | 写清场景、目标、验收标准 |
| 排期 | Backlog / Todo | 决定优先级和负责人 |
| 开发 | In Progress | 从 main 开 feature 分支 |
| 评审 | In Review | 提 PR,等待 CI 和 Review |
| 合并 | Done | PR 合并 main,自动关闭 Issue |
| 验收 | Verified | 按验收标准确认 |

**追踪规则**:分支名带 Issue 号,PR 描述写 `closes #<编号>`。

## 4. 需求清单

### US-1 初始化项目工程化与 CI/CD · 状态: Backlog

作为 **项目开发者**,
我想要 项目具备基础工程结构、测试、CI 与 CD,
以便 后续每次开发都能自动检查并自动部署。

验收标准:
- AC1: 从 `main` 开 feature 分支完成初始化,不直接 push main。
- AC2: PR 触发 CI,至少包含格式检查、静态检查、单元测试、构建检查。
- AC3: CI 全绿后合并 main。
- AC4: 合并 main 自动触发 CD,部署后健康检查通过(端口 8888 / `/_stcore/health`)。
- AC5: 完成后更新 `standards/PROGRESS.md`。

### US-2 数据分析交互页面 · 状态: Backlog

作为 **银行营销分析师**,
我想要 在 Web 页面上查看数据概览、字段分布与目标变量分布,并能按条件交互筛选、切换图表,
以便 在建模前理解「哪些客户更容易认购」,指导后续特征选择与营销策略。

验收标准:
- AC1: Given 应用已启动并打开分析页,Then 展示数据概览(行数、列数、字段类型、缺失情况)。
- AC2: Then 展示目标变量 `subscribe` 的分布(认购/未认购占比)。
- AC3: Then 提供至少 3 类可视化:目标变量分布、分类字段分布、数值字段分布。
- AC4: When 用户在筛选器选择字段/取值,Then 图表与统计随筛选联动更新。
- AC5: Given 2 万+行数据,When 页面加载与筛选,Then 单次交互在合理时间内完成(如 ≤ 3s)。
- AC6: 数据加载与统计计算等核心逻辑有单元测试覆盖。

技术备注:
- 可视化库选 Streamlit 内置(原生图表或可选配 plotly),避免引入过重依赖。
- 分析计算写成纯函数(`eda.py`),与 UI 分离,便于测试与复用。

### US-3 离线训练「是否认购」二分类模型 · 状态: Backlog

作为 **数据科学家**,
我想要 基于训练数据离线训练一个预测「是否认购」的二分类模型,并输出可复现的性能指标,
以便 只有效果达标的模型才进入在线预测。

验收标准:
- AC1: Given 已提供 `data/train.csv`,When 执行训练命令(如 `python -m src.banksys_sy_liujunyan.train`),Then 训练成功并生成模型产物与指标报告。
- AC2: Then 训练/验证集划分使用固定随机种子,重复运行结果一致(可复现)。
- AC3: Then 输出二分类指标(AUC、F1、精确率、召回率),AUC ≥ 0.80(基线,以数据探索后校准)。
- AC4: Then 模型产物(模型文件 + 特征配置)可被预测模块稳定加载。
- AC5: When 对同一输入重复预测,Then 输出完全一致。

技术备注:
- 类别不均衡:目标列 `subscribe` 正例占比低,需评估是否需要重采样(如 SMOTE)或调整阈值。
- `duration` 字段**保留参与建模**(经人类确认)。已知其存在未来信息泄漏风险,但按需求保留;预测页须如实展示该输入项及其含义。
- 特征处理(编码/缩放)必须与预测模块共用同一套逻辑,避免训练/预测不一致。

### US-4 在线预测系统(点选式输入) · 状态: Backlog

作为 **银行营销人员**,
我想要 在 Web 页面上通过下拉/单选/数字输入的方式录入客户属性与营销上下文,点击「预测」,
以便 实时判断该客户是否会认购定期存款,并据此安排营销资源。

验收标准:
- AC1: Given 打开预测页,Then 所有模型输入字段均以点选/下拉/数字控件呈现,无需手写自由文本。
- AC2: Given 输入合法,When 点击「预测」,Then 显示是否认购结论与认购概率,响应时间 ≤ 2s。
- AC3: Given 输入非法(缺失必填、越界数值),When 点击「预测」,Then 给出明确错误提示且应用不崩溃。
- AC4: 预测逻辑(输入转换 + 模型推理)有单元测试,同一输入输出稳定一致。
- AC5: 预测阈值可配置,页面清晰展示结论依据。

技术备注:
- 预测页输入控件的取值域必须与训练数据中的类别保持一致(如 job/month 的候选值)。
- 模型缺失时(未训练)预测页应给出可操作的提示,而不是报错崩溃。

## 5. 非功能需求

- **安全**:密钥只进 Secrets,不进 Git。
- **可维护**:一需求一小 PR,避免大爆炸式提交。
- **可测试**:核心逻辑必须有单元测试;本地/CI 由 AI 执行自检。
- **可部署**:容器名 `banksys_sy_liujunyan`,端口 8888;部署后健康检查 `/_stcore/health`。
- **性能**:数据规模约 3 万行;预测响应 ≤ 2s,分析页单次交互 ≤ 3s。
- **可复现**:训练固定随机种子;数据进 Git,干净环境可复现 CI。
- **可运行**:容器启动即拉起 Streamlit 应用(含模型自检/自动训练兜底,方式见 PROGRESS/ADR)。
